# 发布规划

目标：尽早公开，争取时间优势；但公开前必须过完"不可逆"的那几关。制定日期 2026-11-15，日期是目标，不是承诺。

## 定位

**本地、离线、面向私人文档的长文档翻译与重排版工具。**

- 给谁用：手里有不能外传的外文资料（厂商手册、内部文档、合同附件、自购的技术书）的个人和小团队。
- 和"保留原版式、原位替换文字"的工具（如 BabelDOC / PDFMathTranslate）的区别：
  - 产出的是**重新排版的书**：中文目录、多级书签、对照版，适合从头读。
  - 同时产出干净的 Markdown，可直接进知识库。
  - 术语表可从书后索引自动生成；每次运行出质检报告。
  - 隐私是硬约束：强制本地解析，由测试守护。
- 不做什么：不做云服务，不做在线翻译，不内置任何文档。

## 阶段

### 阶段 0：能稳定自用（已完成）

- 三份结构不同的长文档完整跑通（带编号的书、按书签定级的书、单根书签的手册）。
- 质检报告、防泄露钩子、隐私检查。
- 离线操作手册。

### 阶段 1：别人能装上（目标 2026-12-06，私有仓库内完成）

退出标准：一个没参与过开发的人，照着文档在一台新机器上装好并跑通一份文档。

- [ ] CI 门禁全绿：防泄露、静态检查、漏洞审计、Linux 三个 Python 版本。
- [ ] macOS、Windows 的测试任务跑通（先保证排版和测试，解析和翻译靠各平台的 MinerU、Ollama）。
- [ ] 在第二台机器上从零安装一次，把踩到的坑补进手册。
- [ ] 小显存验证：用一个 8 GB 显存能跑的模型翻一章，记录质量和速度，给出选型建议表。
- [ ] `doctrans init`：一条命令建好数据工作区目录。
- [ ] 英文 README；手册保留中文。
- [ ] 打标签 `v0.2.0`，验证发布流程。

### 阶段 2：公开预览（目标 2026-12-20）

退出标准：仓库公开，标注 alpha，外部的人可以提 Issue 和 PR。

公开前检查清单（这些事做错了收不回来）：

- [ ] **历史记录扫描**：对全部提交历史（不只是当前文件）跑敏感词检查，确认从未提交过书名、作者、文档片段。有问题就在公开前重写历史。
- [ ] 提交者邮箱全部是 GitHub 隐藏邮箱。
- [ ] 示例只用自有或开放许可的文档（比如自己写的样例手册、CC 许可的论文），并注明来源和许可。
- [ ] README 写明用途边界：只处理你有权使用的文档。
- [ ] 开启分支保护：必须走 PR、必须过 CI、框架文件必须代码负责人批准、禁止强推。（公开仓库免费可用。）
- [ ] 开启私密漏洞报告、Dependabot 告警。
- [ ] 准备一段演示：一份开放许可的文档，原文和成品对照截图。

### 阶段 3：扩大适用面（公开后按反馈排序）

文档类型（每类先找一份可公开的样本，做成测试）：

| 优先级 | 场景 | 现状 |
|---|---|---|
| 高 | 没有书签也没有编号的 PDF | 标题层级无法确定，需要按字号/版式推断 |
| 高 | 扫描件（OCR） | 未验证 |
| 中 | 双栏排版（论文、期刊） | 未验证跨栏拼段 |
| 中 | 公式多的文档 | 只处理过"代码被误认成公式" |
| 中 | 日语、俄语等其它源语言 | 语言表只有六种欧洲语言 |
| 低 | 脚注、页边注多的书 | 未验证 |
| 低 | 幻灯片导出的 PDF | 未验证 |

功能：

- EPUB 输出（手机和阅读器上读）。
- 目标语言可配置（现在固定为简体中文）。
- 本地网页界面：拖入文件、看进度、看质检报告。面向不用命令行的人，也是跨平台最省事的"客户端"形态。
- DOCX / PPTX：直接改原文件里的文字，另一条流程。

## 平台策略

| 平台 | 做法 |
|---|---|
| Linux / WSL2 | 主力平台，完整验证 |
| macOS | 原生支持为目标。CI 先保证排版和测试；解析、翻译用 macOS 版的 MinerU 和 Ollama |
| Windows | 短期推荐 WSL2。原生支持取决于 CI 结果：排版库在 Windows 上要额外装 Pango |
| 没有独立显卡 | 能跑但慢：小模型 + MinerU 轻量档。给出明确的预期时间 |

不做各平台的原生安装包。跨平台靠三样：纯 Python 的代码、各平台都有的 MinerU 和 Ollama、将来的本地网页界面。

## 风险

| 风险 | 应对 |
|---|---|
| 被用于翻译盗版书，项目被贴上标签 | 文档和示例只围绕"自有/公开/已授权文档"；不提供任何去水印、绕过保护的功能 |
| 同类项目先做了"重排成书" | 尽早公开；把质检报告和隐私守护做成可见的差异点 |
| AGPL 让部分公司不敢用 | 依赖决定的，无法改变；在 README 说明"自己用、不分发就不受影响" |
| 上游 MinerU 命令行大改 | 只依赖 5 条命令；`docs/dependencies.md` 记录接口；每次升级跑回归 |
| 只有一个维护者 | 门禁全部自动化；框架和规则分层，让外部贡献集中在风险低的规则层 |

## 版本约定

- `0.x`：配置字段只增不改；缓存格式向后兼容。
- 补丁版本（`0.2.1`）：只修缺陷和安全问题。
- `1.0` 的条件：阶段 3 的"高"优先级场景完成，三个平台有人实际用过。
